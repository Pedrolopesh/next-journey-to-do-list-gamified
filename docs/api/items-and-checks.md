# Items, categories and checks

Code in `apps/api/src/modules/items` and `modules/categories`. The EXP and coin rules are in [progression-and-game.md](progression-and-game.md).

## Items

- Three types: daily (has a frequency, in weekdays 0 to 6), task (optional due date) and habit. The **type never changes**; frequency only on a daily and due date only on a task.
- The list (`GET /v1/items`) already comes with the state of the day: done, overdue, streak and counters. A completed task leaves the list and goes to the history.
- The user only uses **their own categories** (IDOR protection): someone else's category is `404`.
- **Soft delete**: the EXP history is kept (RF-16).
- **History** (`GET /v1/items/history`): completed tasks, from newest to oldest, only the user's own, paginated by `before` (completion instant). The route is declared before `:id` so it is not read as an id.
- **Starter items:** created by the server when the account becomes valid (`items/starter-items.ts` and `StarterItemsService`), once, only for an account with no items. An example does not increment `items_created`.
- Deleting a category with active items requires the destination category (`moveTo`).

## Check (`POST /v1/items/:id/checks`)

A **single transaction**: validates, saves the check, updates EXP, level and coins, the chapter of the active story, the daily streak and the achievements.

- **Idempotent by `checkId`** (UUID generated by the app): repeating returns exactly the same result, without duplicating EXP (with the achievements, in the first response).
- **Serialized per user:** the action locks the active user's statistics row. A concurrent call with the same `checkId` waits and, once in, already sees the check saved by the first.
- **EXP only once** when the item is unchecked and checked again: the coins are earned, the EXP is not. A task is worth **once in a lifetime** (unchecking on another day does not release the EXP again); a daily and a habit, **once per day** (the next day is a truly new check).
- The completed chapters (one per level gained) are saved and the response brings the modal of the last one (RF-28).
- The check is saved **before** the achievements are evaluated, so the balance and flame ones see this check.

## Uncheck (`DELETE /v1/items/:id/checks/:checkId`)

On any day and chapter. EXP, level and chapter stay as they are; only the coins decrease (the loss of the current chapter, never below zero). The streak and the days with a check are recomputed from the active checks that remain.
